<CardGrid>
  <Card title="One merged endpoint" icon="puzzle">
    Clients declare a single server. Tools come back as `<server>-<tool>`, filtered by what the key may see.
  </Card>
  <Card title="Known versions" icon="list-format">
    Packages are installed by the hub, never `npx -y`. Pin a version, or let the hub track it and update in one click.
  </Card>
  <Card title="Safe updates" icon="rocket">
    The new version starts next to the old one and takes over only once it answers. The previous one stays for rollback.
  </Card>
  <Card title="Keys with scopes" icon="approve-check">
    One bearer key per client, limited to servers and tool globs. Tokens are shown once and stored hashed.
  </Card>
  <Card title="Behind your identity provider" icon="seti:lock">
    The web UI signs in with OpenID Connect: PocketID, Authelia, Keycloak. No local password to leak.
  </Card>
  <Card title="Small on purpose" icon="star">
    One YAML file, a few environment variables, one Docker image. No database, no marketplace, no build step.
  </Card>
</CardGrid>

## Configured by one file

Servers live in a YAML file you can version. Secrets come from the environment and never reach a server that did not ask for them.

[Read the server file reference](configuration.html)

</div>
<div>

```yaml title="mcpyard.yaml"
servers:
  time:
    package: { pypi: mcp-server-time }
  memory:
    package:
      npm: "@modelcontextprotocol/server-memory"
      version: "2026.8.31"   # pinned
  search:
    url: https://search.example.lan/mcp
    headers:
      Authorization: Bearer ${SEARCH_TOKEN}
    tools: { deny: ["*_delete"] }
```

</div>

<section class="why">

## Why another hub?

Heavier hubs carry a marketplace, smart routing and a database. Light proxies expose one route per server, so every client has to declare every server. MCP Yard sits in between: one merged endpoint, known versions, scoped keys and an OIDC web UI, and nothing more.
